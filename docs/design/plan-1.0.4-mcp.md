# FutureShell 1.0.4 开发计划

更新于 2026-11-07。版本号暂定 1.0.4，基线为已发布的 `v1.0.3`（`0c0a666`）。本文供实现与复审使用。工作区已有 `press_enter` 和工具说明改动，已通过本地验证。连接发现、应用授权界面和整体验收待实施。

## 一、交付目标

外部 AI 能从 MCP 工具清单找到已获准使用的连接，打开新会话，读取提示符，提交选项或命令，再从终端确认结果。用户可以在 FutureShell 里完成工具授权和单条连接授权。新客户端的验证以实际选择并完成这条链路为准。

| 能力 | 本版选择 | 依据 |
| --- | --- | --- |
| 提交终端输入 | 扩展 `terminal.send`，可选 `press_enter` | 与应用组合命令栏的 Enter 行为一致，保留旧调用的字节语义，复用同一个 PTY 写入口。 |
| 查找已保存连接 | 增加独立授权的 `profiles.list` | 已保存连接和正在运行的会话有不同的 ID 与授权范围。独立工具可单独关闭连接发现。 |
| 引导 AI 选择通道 | 在 MCP 工具描述及参数 schema 说明使用顺序，应用设置页写明授权步骤 | 工具描述随 `tools/list` 下发。客户端据此区分交互终端和独立 SSH exec 通道。 |

协议仍为现有本机 MCP 桥。本版范围为 SSH 连接发现与交互终端；RDP、串口、新传输和自动识别各品牌堡垒机菜单留在后续版本。提示符、资产编号和实际登录目标以实时读取结果为准。

## 二、接口与应用改动

### 连接配置发现

- `profiles.list` 无必填参数，首版接受空参数对象。返回结构化对象 `{"profiles":[{"profile_id":"<配置 UUID>","name":"<用户设置的连接名>"}]}`。按名称和 UUID 稳定排序，重名保留各自的 ID。仅给出重名标签时，AI 应请求用户提供具体配置 ID，或让用户先改成不同的名称。
- 复用 `ProfileRepo::list_with_diagnostics` 的存量解码。在应用端筛选 `Protocol::Ssh` 且 `ai_policy.mcp_allowed == true` 的有效配置，再投影为仅含 ID 和名称的 DTO。坏行跳过，数据库整体读取失败返回通用工具错误。回包不含坏行内容、主机、端口、用户名、跳板链、环境变量、凭据引用或 Vault 数据。结构化输出沿用已有脱敏链。
- 扩展 `SessionDirectory` 及应用适配器，保持 `sessions.list` 现有返回形状。新工具走清单、按名授权、只读分级、执行和审计。AI 关闭档拒绝调用；只读档允许已授权的列表查询，`sessions.open` 仍按写入级别处理。
- 工具在「设置 → AI → 对外 MCP 服务」中单独勾选，默认关闭。现有 MCP 服务在客户端建立连接时读取工具名单，设置页明确提示修改后断开旧连接并重连；验收分别检查重连前后，避免把客户端缓存误判为授权失效。
- 连接编辑器的 AI 页增加「允许 MCP 发现并打开此 SSH 连接」，复用 `ai_policy.mcp_allowed` 和现有保存路径，只修改该字段并保留其他 AI 策略。新建及缺字段的旧配置默认关闭，已保存的授权可在同一入口核对与撤销。外部 JSON 导入时把该字段重置为 `false`，授权由本机用户重新选择。现有本机配置不做批量改写。
- 列表每次读库，列表结果仅用于发现。打开时继续检查工具权限和目标配置权限，并在确认结束后、读取凭据或拨号前，用本次用于连接的同一份 SSH 配置再次检查权限和协议。等待确认时撤销、删除或切换协议的配置不得建立连接。人工连接继续走现有路径；已建立会话的终止由用户在会话管理中操作。

依据 [应用会话适配器](../../app/src/mcp/ports.rs)、[连接仓储](../../crates/connmgr/src/repo.rs)、[MCP 服务分派](../../crates/mcpbridge/src/server.rs)、[连接编辑器](../../frontend/src/components/ProfileDialog.svelte)、[MCP 设置页](../../frontend/src/components/SettingsDialog.svelte)、[客户端授权装配](../../app/src/mcp/mod.rs) 和 [连接装配](../../app/src/commands/session_cmd.rs)。

### 终端输入与工具说明

- 纳入已有本地改动。示例调用参数为 `{"session_id":"<会话 ID>","payload":"p","press_enter":true}`。服务端把单行文本和一个 CR 一次发送。空文本可单独按 Enter，已带 CR 或 LF 的文本搭配 `true` 时返回参数错误。省略或传 `false` 保持原字节，`terminal.send_raw` 保留原契约。
- `terminal.read` 指引先读当前屏幕，`terminal.send` 指引提交后再读结果。工具返回「已发送」时仅表示输入写入成功。远端是否接受输入、切换目标或执行命令，由后续读取确认。结果不明时先看屏幕再决定下一步。联调使用空白的新会话，现有会话有未提交输入时先让用户确认处理方式。
- `command.run` 说明独立 exec 通道的目标是 SSH 连接端点。在 PTY 内进入下游机器后，按 `terminal.send` → `terminal.read` 操作。描述中明确区分 `profile_id` 和 `session_id`，并让 `sessions.open` 指向 `profiles.list`。工具清单缺少连接发现时，可由用户在应用中先打开目标连接，再用 `sessions.list` 取得会话 ID。

依据 [工具清单及参数解析](../../crates/mcpbridge/src/tool.rs)、[MCP 传输](../../crates/mcpbridge/src/transport.rs) 和 [应用组合命令栏](../../frontend/src/App.svelte)。

## 三、实施顺序

| 顺序 | 工作 | 完成条件 |
| --- | --- | --- |
| 1 | 整理已有 Enter 改动、工具描述与设置页术语 | 保留旧参数和风险等级，MCP 协议回归与隔离 SSH 输入验证通过。 |
| 2 | 先落实配置授权与 UI，再接入 `profiles.list` | 用户能在桌面端授权和撤销 SSH 配置。外部导入无法取得授权，确认期间撤销后无法拨号。新工具经独立白名单发现，列表字段通过隔离检查。 |
| 3 | 串起工具发现、打开、读屏、输入和结果确认 | 在受控 SSH 环境中跑协议端到端测试，再用一个实际 AI 客户端从空会话跑一遍。 |
| 4 | 准备候选包和发布资料 | 更新版本一致性载体、更新记录及既有发版检查记录，按仓库发布流程完成三平台 CI 和安装验证。 |

先完成前一阶段的判据再进入后续阶段。实际客户端联调需预留修订工具说明的时间，交付日期以联调结果和三平台流水线为准。发布流程见 [开发与发布指南](../../CONTRIBUTING.md#发布流程)。

## 四、验收与回退

| 场景 | 通过判据 |
| --- | --- |
| 工具发现 | 未勾选的新工具在 `tools/list` 不可见，直接调用同样拒绝。勾选后重连可见，客户端能读到说明和参数类型。客户端应具备本机连接令牌及所需工具权限，测试环境用允许打开会话和发送输入的档位。 |
| 配置授权 | 新建默认关闭，编辑保存与取消行为正确。导入含 `mcp_allowed: true` 的 JSON 后仍关闭。在列表与打开之间撤销、以及等待打开确认时撤销，均须在读取凭据或拨号前拒绝；验证免确认同样无法打开撤销后的连接。 |
| 配置发现 | 无活动会话仍能找到已允许的 SSH 配置。结果只有 ID 和名称，包含重名项，排除未授权、非 SSH、已删除和损坏项。普通 UUID 能直接交给 `sessions.open`，含已知机密的名称经现有脱敏链处理。空集合与读取失败可区分。 |
| 终端回归 | 字节级验证旧调用、`press_enter: false`、文本加 Enter、只按 Enter，以及已含 CR/LF 的双提交防护。只读档、确认档和免确认档分别覆盖。 |
| AI 实际使用 | 从工具清单开始，用用户给出的合成连接名找到 ID，打开会话，读取菜单，提交选项，验证目标身份后执行只读命令。测试菜单只接受 CR，至少复跑一次普通 SSH shell。给客户端的输入只包含任务目标与合成连接名，工具参数由客户端自行选择。全程用原生 MCP 调用，记录工具选择、参数与可核验输出。首次主机密钥验证和凭据交互沿用现有设置。 |
| 发版 | Rust 格式与 Clippy、两种 Rust 测试入口、依赖审计、前端检查和文档门禁均通过。三平台安装包完成安装、启动、覆盖重装与卸载测试。 |

本版复用现有配置字段，计划无需数据库迁移，保持现有最低兼容数据库版本。发现新工具有问题时，取消授权并让客户端重连，再验证该工具不可见、旧工具仍能用。发现单条连接授权有误时，从连接编辑器撤销并重新验证列表和打开请求，按需要关闭已建立的会话。需要回退程序时先备份应用数据，验证备份副本能被旧版读取，再切回 1.0.3 和旧调用参数；已发送到远端的输入须独立查证结果。候选包的回退步骤以测试环境演练为准。


## 五、方案复审记录

| 复审范围 | 核对到的缺口 | 修订与验收 |
| --- | --- | --- |
| 应用授权 | 连接编辑器的 AI 页只有全局设置提示。全局工具名单在连接建立时读取。 | 加单配置开关、默认关闭和重连提示。分别核对配置授权与客户端工具授权。 |
| 数据边界 | `ProfileRepo::import_json` 当前会保留 `mcp_allowed`。如果直接增加目录，外部文件可以预先打开该配置的发现权限。 | 导入路径清除该授权，补带 `true` 的回归样本。保留本机已保存值，由用户核对。 |
| 调用时序 | 当前 `sessions.open` 在等待确认前检查权限，用户响应后才进入实际连接。 | 按本次连接快照补一道权限检查，覆盖确认期间撤销及协议变化。 |
| 端到端验收 | 协议回包成功只证明工具可调用，无法证明实际客户端能自行选对会话和通道。 | 在隔离环境以实际 AI 客户端验证完整工具选择和目标机回显，另跑普通 shell 对照。 |

已完成编写后的接口、安全和验收复核。上述改动及真实 AI 客户端验证仍是实施和发版的待验项。
