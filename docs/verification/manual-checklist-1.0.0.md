# 1.0.0 人工核验清单

> **这份清单存在的理由**：当前汇总 15 项需要真实环境和操作记录的验收，包括后续新增的 rz/sz 与 RDP。
> 它们不是待办，是**待验**。两者的区别很具体：待办可以由我继续写代码消掉，
> 待验不行——我代签就是造假。
>
> 每一项给三样东西：**怎么做**、**看什么**、**算通过的判据**。
> 判据写成可以答「是/否」的形式；答不出「是」就不要打勾。
>
> 填法：在 `结论` 栏写 `通过` / `不通过` / `跳过`，后面跟一句话。
> **不通过和跳过都比假通过有价值**——发布说明里如实列出未验项，读者知道该自己试哪些；
> 假通过则是把风险转嫁给用户。

生成时间：2026-08-26。对应仓库状态：`main` 分支本地 HEAD。

2026-09-05 更新：代码侧修复和本次实际验证见 [1.0.0 发版检查记录](release-readiness-1.0.0.md)。
未填写的真机项目继续保持待验，不以单元测试通过代签。

## 分组二：需要真人在 GUI 里操作（4 项）

出口原文里就写着「手工核验留痕」——这几项的判据本身是「真人走过一遍」。

### V3 — 凭据 UI 端到端

- **出口原文**：ProfileDialog 认证页签「存入 Vault…」新建 password 凭据 → 下拉自动回填选中
  → 保存 Profile → 以该密码对 OpenSSH 容器连接成功；Vault 锁定态下该流程给出「vault 未解锁」明确错误。
- **怎么做**：
  1. 起一台可连的 SSH（容器最省事，见文末「起一台测试用 sshd」）。
  2. 应用里新建 Profile → 认证页签 → 点「存入 Vault…」→ 新建一条 password 凭据。
  3. 看下拉是否**自动回填并选中**刚建的那条（不是需要你手动再选一次）。
  4. 保存 Profile → 双击连接。
  5. 锁定 Vault（工具菜单）→ 再连一次。
- **看什么**：第 3 步的下拉选中态；第 5 步的错误文案。
- **判据**：
  - 下拉自动回填并选中了刚建的凭据？
  - 用该凭据连接成功？
  - Vault 锁定后再连，错误文案**明确说了「vault 未解锁」**（而不是一句泛泛的「认证失败」）？
- **为什么 itest 不能替代**：四路认证 itest 走的是代码构造的 Profile，
  绕过了「UI 把凭据存进去、再把它读回来选中」这一段。那一段出错的样子是
  「存是存进去了，下拉里选不中/选错一条」——测试里根本不存在下拉。
- **结论**：

### V4 — Vault 便携解锁 UI

- **出口原文**：删除/屏蔽 keyring 条目后启动 → VaultDialog setup/unlock 双模以应用密码解锁成功
  （错误抖动提示）；自动锁定生效（App 顶层 60s 轮询 `vault.autoLockMinutes` + 最后交互时间戳 → `vault_lock`）。
- **怎么做**：
  1. Windows：`控制面板 → 凭据管理器 → Windows 凭据`，找到本应用的条目，删掉。
     （或用 PowerShell：`cmdkey /list` 找到后 `cmdkey /delete:<target>`。）
  2. 重启应用。
  3. 应当弹 VaultDialog。先**故意输错一次**密码。
  4. 再输对，解锁。
  5. 设置里把 `vault.autoLockMinutes` 调到 1 分钟，然后**不碰应用**等 1 分多钟。
- **看什么**：第 3 步有没有「抖动」提示（不是静默失败）；第 5 步 Vault 是否自动锁上。
- **判据**：
  - keyring 条目没了之后，启动弹的是 VaultDialog 而不是报错/崩溃？
  - 输错密码有可见的错误反馈（抖动）？
  - 输对能解锁？
  - 闲置超过 `autoLockMinutes` 后真的自动锁上了？
- **注意**：删 keyring 条目是**对你这台机器的真实修改**。删之前确认你记得应用密码，
  否则 Vault 里的东西解不开。
- **结论**：

### V11 — Windows 上 agent 真实签名

- **背景**：四路认证已 4/4，但 agent 那一路的**真实签名往返**只在 Linux 上跑过
  （`scripts/linux-itest.sh`）。Windows 走的是 Pageant / 命名管道，那条路径上
  「Ok ⇒ 真能问出身份」有断言，**真签名那一步没跑过**。
- **为什么没跑**：这台机器的 `ssh-agent` 服务是 `Disabled`。启用它要管理员权限，
  且是对你这台机器服务配置的真实修改——那是你的决定，我没动。
- **怎么做**（**会改你机器的服务配置，想清楚再做**）：
  1. 管理员 PowerShell：`Set-Service ssh-agent -StartupType Manual; Start-Service ssh-agent`
  2. `ssh-keygen -t ed25519 -f $env:USERPROFILE\.ssh\fs_test_key -N '""'`
  3. `ssh-add $env:USERPROFILE\.ssh\fs_test_key`
  4. 把 `fs_test_key.pub` 装进某台测试 SSH 的 `authorized_keys`。
  5. 应用里建一个 Profile，认证方式勾「使用 agent」，连接。
- **判据**：连接成功，且状态栏/日志里报的认证方法是 `agent`？
- **验完清理**：`ssh-add -d`、`Stop-Service ssh-agent`、`Set-Service ssh-agent -StartupType Disabled`。
- **结论**：

多个核验项要一台可连的 SSH。最省事的办法（需要 Docker）：

```bash
docker run -d --name fs-verify -p 2222:2222 -e PASSWORD_ACCESS=true -e USER_NAME=verify -e USER_PASSWORD=verify123 -e PUID=1000 -e PGID=1000 linuxserver/openssh-server:latest
```

连接参数：`127.0.0.1:2222`，用户 `verify`，密码 `verify123`。

验完清理：

```bash
docker rm -f fs-verify
```

要 htop/vim（V12）的话另起一台 Debian 的：

```bash
docker run -d --name fs-verify-tui -p 2223:2222 debian:stable-slim sh -c "apt-get update -qq && apt-get install -y -qq --no-install-recommends openssh-server htop vim && useradd -m -s /bin/bash verify && echo 'verify:verify123' | chpasswd && mkdir -p /run/sshd && /usr/sbin/sshd -D -e -p 2222"
```

## V14 — ZMODEM rz/sz 重设计（2026-08-26 新增）

真机手测清单。自动化已覆盖的部分（协议、避让、多文件字节正确性——对真 lrzsz
容器跑过）不重复列；这里只列**只有真用才知道**的手感项。

**前置**：连上 V14-a 那台容器（下附命令），终端里已能跑 `rz`/`sz`。

- [ ] **rz 多选上传**：终端敲 `rz` → 弹出的选择器里 Ctrl 选 3 个文件（其中一个
      0 字节）→ 确认。容器侧 `ls -l` 与 `sha256sum` 逐个核对。
- [ ] **关掉不再弹回**：`rz` 等待期间关掉选择器 → 不再自动重开；条上
      「选择本地文件…」能手动重开；「取消」让远端 rz 干净退出。
- [ ] **层级导航**：选择器里进子目录 → 「上级」/ 面包屑 / `..` 三条路都能回去。
- [ ] **sz 首次引导**：设置里把下载模式清掉（或新装环境）→ `sz` 一个文件 →
      弹「第一次收到文件——保存到哪里？」→ 选目录 + 勾「记住」→ 再 `sz` 一个
      → 不再弹（直接落到记住的目录）。
- [ ] **sz 冲突三选**：往同一目录 `sz` 同名文件 → 弹「覆盖 / 保留两者 / 跳过」；
      三种各试一次（保留两者应得 `name (1).ext`；跳过应**不**产生文件）。
- [ ] **「其余同此处理」**：`sz` 一批同名文件（`sz a.txt a.txt.bak` 不行——
      得真同名：先 `cp a.txt /tmp/x.txt` 再分两次 `sz`）→ 第一个冲突勾上
      「对本次其余文件采用相同处理」→ 后续不再弹。
- [ ] **「不选了」兜底**：引导框直接点「不选了」→ 文件落到建议目录（不丢）。
- [ ] **设置页**：改固定目录 / 切每次询问，改完立即生效（下一次 sz 就按新的走）。

## V15 — RDP 协议（2026-08-27 新增）

**只有真 Windows 能核验的那部分在这里**。自动化已覆盖的（协议握手、证书
TOFU、扫描码映射、剪贴板编码、音频解码）不重复列；对真 xrdp 的 itest 证的是
**协议**，证不了真 Windows 的键盘布局、证书链与 NLA 路径——本仓 itest 用的
Debian xrdp **整包无 CredSSP**，NLA 那条判据在它上面是带因跳过的。

**前置**：一台开了远程桌面的 Windows（家庭版不带 RDP 服务端，需专业版及以上）；
连接属性里协议选 RDP、端口 3389、绑定一条 Vault 口令记录。

### V15-a 连接与认证（NLA 那条路）

- [ ] **首连弹证书框**：指纹/主题/签发者/有效期都显示；点「信任并连接」后连上。
- [ ] 状态栏播报「协商安全层：NLA（CredSSP）」——**这条是 xrdp 上跑不到的**。
- [ ] **错口令**：改错 Vault 里的口令重连 → 明确报「认证失败」，
      而不是笼统的「连接失败」。
- [ ] **拒绝证书**：删掉 `rdp_certs` 表里那行（或换台机器）→ 再连时点「拒绝」
      → 报「证书被拒绝」，且**没有**任何认证发生（服务器的失败登录计数不该 +1）。
- [ ] 证书**变更**（在 Windows 上重新生成 RDP 证书后重连）→ 弹框措辞是变更而非首见。

### V15-b 操作手感

- [ ] 键盘：**中文输入法**在远端能正常切换与输入（扫描码路径的真实检验）。
- [ ] 键盘：方向键、Home/End/PgUp/PgDn、右 Ctrl/Alt 都对（extended 族）。
- [ ] 键盘：Ctrl+W / Ctrl+T 不透传（本地快捷键留在本地）。
- [ ] 鼠标：拖拽选择、右键菜单、滚轮上下都对；**缩放窗口后点击不偏移**。
- [ ] 画面：拖动窗口大小 → 远端分辨率跟随（约 250ms 后变化）。
      服务器不支持时应看到一句「该服务器不支持动态分辨率」而不是无声无息。

### V15-c 剪贴板

- [ ] 本机复制一段中文 → 点进 RDP 画布 → 远端记事本粘贴，内容正确**且无尾随乱码**
      （结尾 NUL 那条判据的真实检验）。
- [ ] 远端复制 → 本机粘贴，内容正确。
- [ ] 复制含 emoji 的文本，两个方向都不损坏。

### V15-d 音频

- [ ] 远端播放声音（如系统提示音）→ 本机听得到。
- [ ] 连续播放一段音乐 → **不应有持续的「咔哒」声**（排程正确性的真实检验）。
- [ ] 关闭标签 → 声音立即停止（AudioContext 被释放）。

### V15-e 跳板与重连

- [ ] 配一条跳板（SSH 机器）→ 经它连内网 Windows 的 RDP，能连上。
      逐跳的主机密钥确认框应逐个弹出。
- [ ] 拔网线/断 VPN 制造断线 → 画面上出现「连接已断开」覆盖层，
      **最后一帧仍可见**（不是纯黑）。
- [ ] 点「重新连接」→ 重新登录并回到桌面。
- [ ] 在远端**注销**（不是断线）→ 不应弹「重新连接」（用户就是要退出）。

### V15-f 边界

- [ ] RDP 标签上按 Ctrl+Shift+A（AI）→ 提示「AI 功能不支持 RDP 会话」而不是静默无效。
- [ ] 未绑定 Vault 口令记录的 RDP 配置 → 连接时明确提示去配凭据，不是空口令重试。
